# انطلاقة – للتجارة الإلكترونية V3

نسخة تطوير لمنصة انطلاقة كمنظومة متكاملة للتاجر وصاحب المشروع الرقمي، من الفكرة إلى التشغيل والتسويق والنمو.

## التشغيل المحلي
1. ثبّت Node.js 18 أو أحدث.
2. انسخ `.env.example` إلى `.env` أو مرر المتغيرات من بيئة الاستضافة.
3. شغّل: `npm start`
4. افتح: `http://localhost:3000`

## إعداد الإنتاج
- اضبط `NODE_ENV=production` و`ADMIN_TOKEN` بقيمة سرية قوية في إعدادات الاستضافة. سيرفض الخادم التشغيل برمز الإدارة الافتراضي.
- اجعل `DATA_DIR` مسارًا دائمًا خارج مجلد المشروع لتبقى الطلبات والعملاء محفوظين عند إعادة نشر الكود، مع نسخ احتياطي لهذا المسار. لا ترفع ملفات البيانات إلى GitHub.
- اضبط `PORT` وفق المنفذ الذي تحدده الاستضافة، واربط النطاق وHTTPS بعد إنشاء التطبيق المستقل ضمن الاشتراك.

## أهم الصفحات
- `/index.html` الواجهة الرئيسية ورحلة المشروع والخدمات.
- `/start-project.html` صفحة «ابدأ مشروعك الإلكتروني» لاختيار نوع الموقع والسعر المبدئي وإرسال وصف المشروع.
- `/digital-store.html` متجر المنتجات الرقمية.
- `/product-checkout.html` مسار شراء المنتج الرقمي.
- `/contract.html` الاتفاق والعقد المبسط.
- `/tracking.html` تتبع الطلب.
- `/admin.html` لوحة الإدارة.

## ما يعمل الآن
- الطلبات والعقود والتتبع ولوحة الإدارة.
- طلبات إنشاء المواقع عبر صفحة «ابدأ مشروعك الإلكتروني» وتخزينها في لوحة الإدارة.
- المساعد الذكي عند إضافة `OPENAI_API_KEY`.
- كتالوج المنتجات الرقمية وطلبات الشراء بحالة انتظار الدفع.
- حماية ملفات البيانات من الوصول العام.

## قبل الإطلاق التجاري
- ربط بيانات الدفع الفعلية عبر مبسط/بوابة الدفع واعتماد webhook موثوق.
- إنشاء ملفات المنتجات النهائية ووضعها في مساحة خاصة غير قابلة للوصول المباشر.
- إصدار رابط تحميل قصير العمر بعد تأكيد الدفع فقط.
- ربط إرسال البريد للفاتورة ورابط التحميل.
- اعتماد الشعار النهائي والاسم التجاري بعد التحقق النظامي المناسب.
- تغيير `ADMIN_TOKEN` إلى قيمة سرية قوية.

## إعداد تطبيق Hostinger
- المصدر: `rfrfmnst-cell/-`، الفرع `main`.
- نوع التطبيق: Node.js، والإطار `Other`.
- مجلد المشروع ومجلد المخرجات: `.`.
- أمر البناء: `npm run build`.
- ملف الدخول: `server.js`، وأمر التشغيل: `npm start`.
- اضبط `NODE_ENV=production` و`ADMIN_TOKEN` السري في لوحة الاستضافة قبل التشغيل.
- تحقق من `/api/health` بعد النشر. نجاح رفع GitHub وحده لا يؤكد النشر.
- تأكد من دعم التخزين الدائم واضبط `DATA_DIR` قبل استقبال بيانات عملاء حقيقية.
